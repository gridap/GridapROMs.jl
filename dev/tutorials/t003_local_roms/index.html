Tutorial 3: Local reduced operators

In this tutorial we learn

  • why a single (global) reduced subspace can be a poor choice
  • how local reduced operators are built, stored and evaluated
  • how to trade the number of clusters against the number of snapshots per cluster

Motivation

A linear ROM approximates the solution manifold $\{u_\mu\}_{\mu \in \mathcal{D}}$ with a single subspace. When the solutions change a lot across $\mathcal{D}$ (moving fronts, boundary layers, transport-dominated phenomena), the dimension of this subspace grows quickly with the required accuracy, and so does the online cost.

A local ROM partitions the parameter space into clusters, and builds a reduced operator per cluster. Each local subspace only has to approximate the solutions in its own region of $\mathcal{D}$, which requires fewer modes. Online, the parameter selects its cluster, and the corresponding (small) reduced problem is solved.

The problem

We consider an advection-diffusion problem on $\Omega = (0,1)^2$:

\[-\epsilon \Delta u + b_\mu \cdot \nabla u = 1 \ \text{in } \Omega, \qquad u = 0 \ \text{on } \partial\Omega,\]

with advection velocity $b_\mu = (\cos\mu_1, \sin\mu_1)$ and diffusion $\epsilon = \mu_2$, for $\mu \in [0,2\pi] \times [0.02,0.1]$. The boundary layer forms on the outflow side, and rotates with the advection direction:

using Gridap
using GridapROMs
using Plots

D = ParamSpace((0.0,2π,0.02,0.1))

model = CartesianDiscreteModel((0,1,0,1),(40,40))
Ω = Triangulation(model)
dΩ = Measure(Ω,2)

reffe = ReferenceFE(lagrangian,Float64,1)
V = TestFESpace(Ω,reffe;conformity=:H1,dirichlet_tags="boundary")
U = ParamTrialFESpace(V)

ϵ(μ) = x -> μ[2]
ϵμ(μ) = parameterise(ϵ,μ)
b(μ) = x -> VectorValue(cos(μ[1]),sin(μ[1]))
bμ(μ) = parameterise(b,μ)

a(μ,u,v) = ∫(ϵμ(μ)*∇(v)⋅∇(u))dΩ + ∫(v*(bμ(μ)⋅∇(u)))dΩ
l(μ,v) = ∫(v)dΩ

feop = LinearParamOperator(l,a,D,U,V,FEDomains((Ω,),(Ω,)))
solver = LUSolver()
"Gridap.Algebra.LUSolver"

  pts = [Point(x,y) for x in xs, y in xs]

  heatmap(xs,xs,permutedims(vals);aspect_ratio=:equal,framestyle=:box,
    xlims=(0,1),ylims=(0,1),c=:viridis,titlefontsize=10,kwargs...)
end

μ = Realisation([[0.0,0.05],[π/2,0.05],[5π/4,0.05]])

end

Local ROMs

A local ROM is obtained with the keyword compression=:local, which takes the number of clusters ncentroids:

local_reduction = Reduction(1e-3,H1();nparams=100,compression=:local,ncentroids=4)
GridapROMs.RBSteady.LocalReduction{GridapROMs.RBSteady.SearchSVDRank, H1, PODReduction{GridapROMs.RBSteady.SearchSVDRank, H1}}(PODReduction{GridapROMs.RBSteady.SearchSVDRank, H1}(GridapROMs.RBSteady.SearchSVDRank(0.001), H1(), 100), 4)

This is a LocalReduction wrapping the POD reduction. The RBSolver built from it is a LocalRBSolver, and the residual and Jacobian hyper-reductions are local as well:

local_rbsolver = RBSolver(solver,local_reduction;nparams_res=20,nparams_jac=60,verbose=false)
local_rbop = reduced_operator(local_rbsolver,feop,fesnaps)
x̂_local = solution_snapshots(local_rbsolver,local_rbop,μon)
rom_performance(local_rbsolver,local_rbop,x,x̂_local).error
0.010913915362020448

How local operators are structured

The offline phase proceeds as follows:

  1. the snapshot parameters are clustered with k-means;
  2. the snapshots of each cluster are compressed separately. The resulting LocalProjection stores one projection per cluster, together with the k-means result;
  3. the residual and Jacobian snapshots are clustered in the same way, and each cluster is hyper-reduced separately. Each local hyper-reduction is then projected onto each local subspace, so the hyper-reduced residual stores a matrix of reductions, indexed by (hyper-reduction cluster, subspace cluster).

Here are the training parameters, coloured by cluster, together with the centroids:

using GridapROMs.ParamDataStructures: get_realisation, get_params

k, = get_clusters(local_rbop.trial.subspace)
μtrain = reduce(hcat,get_params(get_realisation(fesnaps)))
scatter(μtrain[1,:],μtrain[2,:];group=k.assignments,markersize=4,framestyle=:box,
  xlabel="μ₁",ylabel="μ₂",legend=:outerright,size=(600,350))
scatter!(k.centers[1,:],k.centers[2,:];marker=:star5,markersize=10,c=:black,label="centroids")

Since the parameter space is not rescaled, k-means splits it along $\mu_1$, which is the parameter that the solutions depend on the most.

Online, each parameter selects the cluster of its closest centroid, and the corresponding local reduced operator, a standard RBOperator, is extracted and solved:

Local operators are saved and loaded exactly as global ones, with save and load_operator. They are compatible with all the features presented in Tutorial 2: TT-SVD, supremizer enrichment, linear/nonlinear splitting, transient problems, and the hyper-reduction strategies.

Accuracy versus dimension

Let us compare global and local ROMs for decreasing tolerances, as a function of the (average) dimension of the reduced subspaces:

tols = [3e-2,1e-2,3e-3,1e-3,3e-4]

function convergence(ncentroids)
  map(tols) do tol
    compression = ncentroids == 1 ? :global : :local
    red = Reduction(tol,H1();nparams=100,compression,ncentroids)
    rbs = RBSolver(solver,red;nparams_res=20,nparams_jac=60,verbose=false)
    op = reduced_operator(rbs,feop,fesnaps)
    x̂ = solution_snapshots(rbs,op,μon)
    projs = ncentroids == 1 ? [op.trial.subspace] : local_vals(op.trial.subspace)
    n = sum(p -> size(get_basis(p),2),projs) / length(projs)
    n,rom_performance(rbs,op,x,x̂).error
  end
end

plt = plot(;xlabel="reduced dimension",ylabel="relative error",yscale=:log10,
  framestyle=:box,size=(600,400))
for ncentroids in (1,2,4,8)
  res = convergence(ncentroids)
  label = ncentroids == 1 ? "global" : "local, $ncentroids clusters"
  plot!(plt,first.(res),last.(res);marker=:circle,lw=2,label)
end
plt

For a given dimension, local ROMs are considerably more accurate: equivalently, they reach a given accuracy with smaller (hence cheaper) reduced problems. The number of clusters is a trade-off: more clusters yield smaller local subspaces, but each of them is trained on fewer snapshots, which eventually limits the accuracy that can be reached. The function compute_ncentroids suggests a number of clusters from the training parameters, with an elbow criterion on the k-means variance:

compute_ncentroids(get_realisation(fesnaps))
10
Note

Hyper-reduction is local too, so each cluster must contain enough residual and Jacobian snapshots to capture the variability of the operators within it. Increase nparams_res and nparams_jac together with the number of clusters.
